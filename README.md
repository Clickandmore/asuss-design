# لوحة تحكم أسس الإنجاز — Design Kit

نسخة ثابتة من تصميم لوحة التحكم في مشروع **asuss** (Laravel 8)، مستخرجة من الشاشات الحقيقية كما تُعرض، مع كل ملفات التصميم.
الهدف: أن يعمل عليها المصمم وClaude (Claude Design أو Figma أو كود مباشر) بدون الحاجة لتشغيل Laravel أو قاعدة البيانات، ثم تُنقل التعديلات إلى asuss.

> **البيانات وهمية.** الأسماء وأرقام الجوال والهوية والجواز والإيميلات والصور الشخصية استُبدلت وقت الاستخراج. القوائم الطويلة قُصّت (10 صفوف لكل جدول، و25 خيارًا لكل قائمة منسدلة).

## التشغيل

```bash
cd asuss-admin-design
python3 -m http.server 8791
# افتح http://127.0.0.1:8791  ← يفتح تسجيل الدخول مباشرة
# كل الشاشات: http://127.0.0.1:8791/gallery.html
```

لا تفتح الملفات بالنقر المزدوج (file://): الجداول تقرأ بياناتها عبر JavaScript وتحتاج خادمًا محليًا.

## إعادة التصميم — المرحلة 1 (24-11-2026)

بهوية نظام التصميم «أسس الإنجاز» (navy ‎#191936، blue ‎#1D70B7، brand ‎#1a5f9e). الخط **Readex Pro** بدل IBM Plex Sans Arabic (مقارنة الخطوط في `kit/fonts.html`).

| الشاشة | ما تغيّر |
|---|---|
| تسجيل الدخول | عمود النموذج (الشعار أعلاه، «تسجيل الدخول»، الحقلان، «تذكرني» و«نسيت كلمة المرور؟»، الزر، سطر المساعدة، وفي الأسفل الحقوق وEnglish) + لوحة كحلية فيها العنوان «رحلة كل عاملة، من التعاقد حتى الوصول» وصورة حقيقية من لوحة المعلومات الجديدة في إطار، وفوقها بطاقة عقد بمراحله الست. على الجوال: النموذج في بطاقة واللوحة مخفية. في الكيت البيانات معبّأة والدخول يذهب للوحة المعلومات (`kit/kit-login.js`، لا يُنقل لـ asuss). |
| لوحة المعلومات | أربعة أرقام للشهر مع خط اتجاه 12 شهرًا ← «يحتاج إجراء اليوم» بجانب «أين تقف العقود» ← «الأداء حسب الإدارة» بتبويبات هي نفس أقسام القائمة (أرقام + رسم + توزيع لكل إدارة) ← آخر العقود. |
| التقارير | شاشة جديدة: قائمة تقارير مجمّعة حسب الإدارة، تقرير واحد مفتوح، فلتر الفترة والفرع، تصدير وطباعة، وكل رسم له عرض جدول. الرابط `reports.html#<id>` يفتح تقريرًا بعينه. |
| القائمة الجانبية | شريط أقسام كحلي (7 إدارات: الرئيسية، الاستقدام، التأجير، التشغيل، العملاء، المالية، الإدارة) + لوحة صفحات للقسم المختار فقط، بعناوين صغيرة وبلا قوائم متداخلة. شارة حمراء على القسم الذي فيه ما ينتظر. البحث (`/`) يبحث في كل الأقسام. زر لإخفاء اللوحة والإبقاء على الشريط، ودرج على الجوال. نفس الأقسام تنظّم لوحة المعلومات والتقارير. |

- التنسيق كله في `assets/admin/custom/kit-overrides.css` (بادئة `as-`، فلا يتعارض مع Luno)، والسلوك والرسوم في `assets/admin/custom/asuss-ui.js` بلا مكتبات.
- لتعديل القائمة أو الشريط العلوي أو محتوى الشاشتين: عدّل `kit/redesign/build.py` أو `kit/redesign/pages/*.html` ثم شغّل `python3 kit/redesign/build.py`. لا تعدّل `screens/dashboard.html` و`screens/reports.html` يدويًا.
- أرقام لوحة المعلومات والتقارير عينة للتصميم. ما أخذ من اللقطة الأصلية: إجمالي العقود والطلبات والسير والجنسيات وعقود التأجير.
- باقي النماذج (عقد تأجير، زيارة، شكوى، تعميد، موظف، مستخدم) والإعدادات تُبنى بنفس نمط النموذج؛ هي المرحلة التالية.

> **تسجيل الدخول — المعتمد (أ):** بطاقة بيضاء في منتصف خلفية كحلية (توهج أزرق، شبكة نقاط خفيفة، علامة الشعار باهتة في الطرف)، والشعار الكامل أعلى البطاقة. حُذف الاتجاهان (ب) و(ج).

### السجلات — كل الجداول في شاشة واحدة (`screens/records.html`)

بدل شاشة لكل جدول: الطلبات، عقود الاستقدام، التأجير، الزيارات بالساعة، الإيواء، السير الذاتية، العملاء، الشكاوى، التعميدات، المهام، الموظفون، المستخدمون والصلاحيات — 12 قسمًا في شاشة واحدة، والتبويبات تُظهر أقسام الإدارة المفتوحة فقط بنفس الترتيب: **تبويب القسم ← شرائح الحالة بأعدادها ← بحث وفلاتر القسم ← الجدول ← لوحة تفاصيل جانبية** (↑ ↓ للتنقل بين السجلات، Esc للإغلاق) فيها مراحل العقد كشريط أفقي والإجراء التالي.
- روابط القائمة الجانبية تفتح القسم والحالة مباشرة: `records.html#recruitment/tafwed`، `#maids/reserved`، `#claims/pending`…
- السير الذاتية تُعرض جدولًا أو بطاقات؛ كل جدول: كثافة الصفوف، إظهار وإخفاء الأعمدة، تحديد متعدد بإجراءات جماعية، تصدير.
- إعداد كل قسم (الأعمدة، الحالات، الفلاتر، التفاصيل، الإجراءات) في `kit/redesign/pages/records.html`؛ المحرك في `assets/admin/custom/asuss-records.js`؛ بيانات العينة في `kit/records-mock.js` (لا تُنقل لـ asuss).
- الشاشات القديمة (`clients.html`، `maids.html`، `recruitment-contracts.html`، `employees.html`، `admins.html`، `hourly-visits.html`…) باقية للمرجع فقط.

### نماذج الإضافة وقاعدة التصميم

- **قاعدة التصميم:** القواعد في أول `DESIGN.md`، وشكلها الحي في `screens/patterns.html`: أنواع الشاشات الأربعة، النصوص، الألوان والحالات، الأزرار، الحقول، الجدول، لوحة العرض، الفراغ والرسائل.
- **نموذج موحد** (`.as-form` + `assets/admin/custom/asuss-forms.js`): أقسام مرقّمة، فهرس جانبي يعدّ الناقص في كل قسم، ملخص يتحدّث أثناء الكتابة، أقسام تظهر حسب الاختيار، تحقق من الصيغ، وشريط حفظ ثابت. مطبّق على: `client-create.html`، `maid-create.html` (حسب نوع السيرة: استقدام / تأجير / بالساعة)، `recruitment-contract-create.html`.

## طريقة العمل المقترحة

1. **المرحلة الحالية:** الكيت جاهز. يُرفع في ريبو منفصل.
2. **التصحيح:** نعدّل التصميم هنا (CSS أولًا، ثم HTML الشاشات). كل تعديل في `assets/admin/...` يقابله ملف بنفس المسار في `public/admin/...` في asuss.
3. **النقل إلى asuss:** تعديلات CSS تُنسخ كما هي. تعديلات HTML تُطبق يدويًا على ملف الـ Blade المذكور في `kit/screens.json` (الـ HTML هنا ناتج الـ Blade بعد العرض، وليس الـ Blade نفسه).
4. **الميزات الجديدة:** تُصمم هنا كشاشات أو مكونات جديدة، ثم تُبنى في asuss.

### قواعد

- لا تُضاف بيانات حقيقية إلى هذا الريبو أبدًا. أي استخراج جديد يمر عبر `tools/build_kit.py` لأنه يجهّل البيانات.
- لا تُعدّل `assets/admin/assets/css/luno-style.css` (قالب Luno الأساسي، 36 ألف سطر). التعديلات تذهب إلى طبقة فوقه (انظر DESIGN.md).

## إعادة التوليد (من جهاز فيه asuss وقاعدة البيانات)

```bash
# 1) عرض الصفحات كمستخدم admin بدون متصفح
php tools/snap.php dashboard /abs/path/raw/dashboard.html
XHR=1 php tools/snap.php "admin/clients?draw=1&start=0&length=10" /abs/path/fixtures/clients.json

# 2) قائمة الأسماء للتجهيل (تبقى على الجهاز فقط، لا تُرفع)
#    + ui_vocab.txt و ui_corpus.txt من resources/lang و resources/views حتى لا تُمسح كلمات الواجهة

# 3) البناء: تجهيل + تحويل الروابط + نسخ الملفات
python3 tools/build_kit.py raw/ names_raw.txt /path/to/asuss/public ./
```

`raw/` و`fixtures/` و`names_raw.txt` فيها بيانات حقيقية: تبقى خارج هذا الريبو (محمية في `.gitignore`).

## حدود النسخة الثابتة

- الأزرار التي تفتح نوافذ أو تحفظ بيانات لا تعمل. الشكل موجود، والسلوك يبقى في asuss.
- البحث والفرز والتنقل بين صفحات الجداول يعرض نفس الصفوف العشر.
- روابط القائمة الجانبية لشاشات غير موجودة في الكيت لا تفعل شيئًا (تحمل المسار الأصلي في `data-route`).
- شاشات الرسوم والخرائط (التتبع، المسارات) غير مضمّنة في هذه المرحلة.
